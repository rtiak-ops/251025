# 🏥 開発環境(Dev) vs 本番環境(Prod) 運用マニュアル

このファイルでは、本プロジェクトにおける「2つの環境」の使い分けと、安全な運用の流れを解説します。

---

## 🏎️ ひと目でわかる違い

| 項目 | 🧪 開発環境 (Dev) | 🌐 本番環境 (Prod) |
| :--- | :--- | :--- |
| **目的** | 新機能の開発、バグ修正、テスト | 実際のユーザーへのサービス提供 |
| **デプロイ先** | `develop` ブランチを push すると反映 | `main` ブランチを push すると反映 |
| **データの扱い** | **適当でOK**。リセットしても良い。 | **超厳重**。本物のユーザーデータがある。 |
| **セキュリティ** | 開発用パスワードを使用 | 強固な本番専用パスワードを使用 |
| **コスト** | 夜間は自動停止して節約 | 24時間稼働（必要に応じて） |

---

## 🛠️ 具体的な使い分けフロー

### 1. 【開発】機能を新しく作る
- **ブランチ**: `feature/xxx`
- **作業内容**: 
  - ローカルPCでコードを書く。
  - `$env:TF_VAR_xxx` や `secrets.auto.tfvars` を設定して、TerraformでDev環境を構築。
- **デプロイ**: `develop` ブランチにマージして push。
- **確認**: Dev環境のURLを開いて、AI分解やタスク登録が動くかテストする。

### 2. 【本番】リリースする
- **ブランチ**: `main`
- **作業内容**: 
  - Dev環境で「100%完璧」と確信したら、`develop` を `main` へマージ。
- **デプロイ**: `main` ブランチを push。
- **確認**: 本番環境のURLを開いて、最終確認。

---

## 🔒 セキュリティとパスワードの管理

それぞれの環境で、以下のファイルを使ってパスワードを分離しています。

- **`terraform/envs/dev/secrets.auto.tfvars`**: 開発用。漏れても被害が少ない値にする。
- **`terraform/envs/prod/secrets.auto.tfvars`**: 本番用。絶対に秘密にする。

**【注意】** これらのファイルは `.gitignore` により GitHub にはアップロードされません。別のPCで作業する場合は、手動でコピーするか、再度作成する必要があります。

---

## 💰 コストを抑えるための知恵

本番環境を動かし続けるとAWS料金がかかるため、このプロジェクトでは以下の工夫をしています。

1.  **Dev環境の自動停止**: 
    - 現在、東京時間の夜間（例：18:00〜）は自動で停止するスケジュールが組まれています。
2.  **手動での停止・起動**:
    - しばらく使わない時は、Terraformフォルダで `terraform destroy` を行うか、AWS管理画面から停止してください。
3.  **無料枠の活用**: 
    - インスタンスサイズは `t3.micro` 等の無料枠対象（または安価なもの）に固定されています。

---

## 🚨 やってはいけないこと（禁止事項）

1.  **本番環境(Prod)でいきなり新機能を試す**:
    - 必ず一度 Dev 環境を通してください。
2.  **本番のパスワードを `terraform.tfvars` に直接書く**:
    - 今回リファクタリングした通り、必ず `secrets.auto.tfvars` か環境変数を使いましょう。
3.  **本番データベースのデータを手動で消す**:
    - 復旧が大変です。DB操作は Alembic (マイグレーション) を通して行いましょう。
