# 🌿 Gitブランチ・運用ガイド (Dev/Prod分離版)

このプロジェクトでは、**「開発環境(Dev)でテストし、OKなら本番環境(Prod)へ出す」**という安全な流れをGitブランチで実現します。

---

## 1. ブランチの役割

| ブランチ名 | 役割 | デプロイ先 |
| :--- | :--- | :--- |
| `main` | **本番用**。常に動く完動品のみを置く。 | **本番環境 (Prod)** |
| `develop` | **開発用**。新しい機能を追加・テストする場所。 | **開発環境 (Dev)** |
| `feature/xxx` | **作業用**。特定の機能を作るための使い捨てブランチ。 | なし (ローカルのみ) |

---

## 2. VS Code（エディタ）での操作方法

マウス操作だけで完結する最新のワークフローです。

### ① 新しい作業を始める
1.  左下の **[ブランチ名]**（例: `main`）をクリック。
2.  リストから `develop` を選択。
3.  もう一度 **[ブランチ名]** をクリックし、`+ 新規ブランチの作成...` を選択。
4.  `feature/add-ai-task` と入力して Enter。
5.  右下の **[クラウドアイコン（ブランチを公開）]** をクリックしてGitHubへ送る。

### ② コードを書いてコミットする
1.  左側のメニューから **[ソース管理アイコン]**（3つの点のアイコン）をクリック。
2.  変更されたファイルの横にある `+` ボタンを押す（ステージング）。
3.  上の入力欄にメッセージ（例: `feat: add ai task`）を書き、**[コミット]** ボタンを押す。

### ③ 開発環境(Dev)でテストする
1.  左下の **[ブランチ名]** をクリックして `develop` に戻る。
2.  ソース管理の `...` メニュー（省略記号）から `ブランチ` > `マージ...` を選択。
3.  自分の作業した `feature/xxx` を選ぶ。
4.  **[変更の同期]** ボタンを押してGitHubへ送信。→ **🚀 自動でDev環境へデプロイ！**

### ④ 本番環境(Prod)へリリースする
1.  左下の **[ブランチ名]** をクリックして `main` に切り替える。
2.  同じように `...` メニューから `マージ...` を選択。
3.  `develop` を選んで合流させる。
4.  **[変更の同期]** ボタンを押して完了！→ **🚀 祝！本番環境へデプロイ！**

---

## 3. CLI（コマンド）での操作方法

エンジニアらしくササッと操作したい場合：

```bash
# 作業開始
git switch develop
git pull
git switch -c feature/add-ai-task

# コミット
git add .
git commit -m "feat: xxx"

# 開発環境へ反映
git switch develop
git merge feature/add-ai-task
git push origin develop

# 本番環境へ反映
git switch main
git merge develop
git push origin main
```

---

## 4. 便利な機能

- **[ソース管理] > [コミットのグラフを見る]**:
  拡張機能 `Git Graph` を入れると、線で繋がりが分かって最高に見やすくなります。
- **左端の [青色の線]**:
  ファイルを編集した場所が青く光ります。これをクリックすると、変更前のコードと比較できます。

---
**Tip:** `main` と `develop` への合流は、ブラウザからGitHubの「Pull Request」を使うのが最も安全でおすすめです。
