# 🌐 S3 + CloudFront 配信ガイド (最新版)

フロントエンド（React/Vite）を EC2 から切り離し、**S3** と **CloudFront** で配信するように変更します。
これにより、**爆速の表示、セキュリティの向上、サーバー負荷の軽減**が実現できます。

---

## 🏗️ 構成のメリット
1.  **高速**: 世界中のエッジサーバーから配信されます。
2.  **安価**: データの転送量に応じた課金のみで、EC2を24時間動かすより安くなります。
3.  **安全**: EC2のポートを開ける必要がなく、DDoS攻撃にも強くなります。

---

## 🛠️ ステップ 1: フロントエンドのビルド (ローカルPCで実行)

S3にアップロードするための「完成品 (distフォルダ)」を作成します。

1.  **ターミナルで frontend ディレクトリへ移動**:
    ```bash
    cd frontend
    ```

2.  **API 接続先の設定**:
    ビルド時に EC2 (バックエンド) のアドレスを埋め込みます。
    -   **方法 A: 基本 (コマンドラインで指定)**
        ```bash
        VITE_API_BASE_URL=http://あなたのEC2のIPアドレス npm run build
        ```
    -   **方法 B: 推奨 (環境変数ファイルを作成)**
        `frontend/.env.production` を新規作成し、以下を記述してから `npm run build` を実行します。
        ```text
        VITE_API_BASE_URL=http://あなたのEC2のIPアドレス
        ```

3.  **ビルド実行**:
    ```bash
    npm run build
    ```
    -   完了すると `dist` フォルダが生成されます。

---

## 📦 ステップ 2: S3 バケットの作成とアップロード

1.  **S3 バケットを作成**:
    *   名前: `todo-app-frontend-2025` (世界で一意の名前)
    *   リージョン: `ap-northeast-1` (東京)
    *   **「パブリックアクセスをすべてブロック」はチェックしたまま**にします。

2.  **ファイルをアップロード**:
    *   S3バケットを開き、`dist` フォルダ内の**中身（index.html, assets/ など）**をすべてドラッグ＆ドロップしてアップロードします。

---

## 🚀 ステップ 3: CloudFront (CDN) の設定

1.  **ディストリビューションを作成**:
    *   **オリジンドメイン**: 作成した S3 バケットを選択。
    *   **名前**: 自動入力されます。
    *   **オリジンアクセス**: `Origin access control settings (recommended)` を選択。
    *   **コントロール設定を作成**: 「設定を作成」をクリックし、デフォルトで作成。
    *   **デフォルトルートオブジェクト**: `index.html` と入力 (重要)。
    *   **ビューワー**: `Redirect HTTP to HTTPS` を選択。

2.  **S3 バケットポリシーの適用**:
    *   作成完了後、画面上部に「S3 バケットポリシーを更新する必要があります」という青いバーが出ます。
    *   「ポリシーをコピー」をクリック。
    *   S3 の「アクセス許可」タブ → 「バケットポリシー」の「編集」で貼り付けて保存します。

## ⚙️ ステップ 4: バックエンド (FastAPI) の CORS 設定

CloudFront のドメイン（例: `d123.cloudfront.net`）からのアクセスを許可する必要があります。

1.  **EC2 に SSH 接続**:　RDSも起動（時間かかるため）
    ```bash
    ssh -i "C:\Users\rtiak\Desktop\AWS\EC2\app-key.pem" ec2-user@IPアドレス（停止すると毎回変わる）
    ```

2.  **EC2 上の `.env` を編集**:
    プロジェクトディレクトリに移動して `nano` エディタで開きます。
    ```bash
    cd ~/251025
    nano .env
    ```

2.  **編集と保存の方法 (nano の操作)**:
    *   **移動**: 矢印キーで `CORS_ORIGINS` の行まで移動します。
    *   **編集**: 既存のドメインの後ろにカンマ `,` で区切って CloudFront のドメインを追記します。
    *   **保存**: `Ctrl` + `O` を押し、ファイル名を確認されるのでそのまま `Enter` を押します。
    *   **終了**: `Ctrl` + `X` を押して元の画面に戻ります。

    **編集例**:
    ```bash
    # CloudFront のドメインを追記
    CORS_ORIGINS=https://d123xxxx.cloudfront.net,http://localhost:5173
    ```

3.  **バックエンドを再起動**:
    設定を反映させるためにコンテナを再起動します。
    ```bash
    docker compose up -d backend
    ```

## 💡 注意点 (Single Page Application 対応)

React (SPA) は、`/todos` などのパスでブラウザのリロードを行うと 403 エラーになります。
これを防ぐため、CloudFront で以下の設定を必ず行ってください：

1.  CloudFront の詳細画面で「エラーレスポンス」タブを選択。
2.  「カスタムエラーレスポンスを作成」をクリック。
3.  **HTTP エラーコード**: `403: Forbidden`
4.  **エラーレスポンスをカスタマイズ**: `はい`
5.  **レスポンスページパス**: `/index.html`
6.  **HTTP レスポンスコード**: `200: OK`
7.  (同様に `404: Not Found` についても同じ設定を行うと完璧です)

## 🧹 ステップ 5: 旧構成 (EC2フロント) の停止と整理

RDS起動
新しい CloudFront 経由でサイトが正しく表示され、ログインやタスク追加ができることを確認したら、EC2 側で動いている不要なフロントエンドを停止します。

### 1. docker-compose.yml の編集
EC2 に SSH でログインし、フロントエンドの定義を無効化します。

```bash
cd ~/251025
nano docker-compose.yml
```

`frontend:` という行から始まるセクションを探し、そのブロック全体を `sh` (または行頭に `#`) でコメントアウトするか、削除します。

**修正後のイメージ:**
```yaml
services:
  backend:
    build: ./backend
    # ... 他の設定 ...

  # frontend:  <-- ここから下をコメントアウトまたは削除
  #   build: ./frontend
  #   ports:
  #     - "80:80"
```

### 2. 反映と不要なコンテナの削除
以下のコマンドを実行すると、設定ファイルから消えたサービス（フロントエンド）のコンテナが自動的に停止・削除されます。

```bash
docker compose up -d --remove-orphans
```
*   `--remove-orphans`: 設定ファイルに記載がなくなった古いコンテナを掃除する魔法のオプションです。

### 3. AWS セキュリティグループの整理 (重要)
フロントエンドを S3 + CloudFront に移したため、**EC2 のポート 80 (HTTP) や 443 (HTTPS) をインターネットに開放しておく必要がなくなります。**

1.  AWS コンソールで EC2 の「セキュリティグループ」を開きます。
2.  「インバウンドルールを編集」をクリック。
3.  **HTTP (80)** と **HTTPS (443)** のルールを削除します。
    *   ※ バックエンド API (ポート 8000 など) を直接叩く設定にしている場合は、そのポートだけ残します。
    *   これで、EC2 への不要な攻撃経路を遮断でき、より安全になります。
